
This is the backend update to support vehicle-type-based pricing in trip creation and pricing management. Follow all steps in order. No frontend changes in this task.
Step 1 -- New vehicle types endpoints
Create artifacts/api-server/src/controllers/vehicleTypeController.ts with these functions:
listVehicleTypes -- GET handler. No auth required (Trip Admins need this during trip creation, public read is fine). Returns all active vehicle types ordered by loading_fee ASC. Each row returns: id, name, loadingFee, unloadingFee.
updateVehicleType -- PATCH handler for /vehicle-types/:id. Super Admin only. Accepts loadingFee and unloadingFee in kobo (both must be positive integers). Updates the vehicle type. Returns the updated row.
Create artifacts/api-server/src/routes/vehicleTypes.ts:
GET  /vehicle-types        (no auth) → listVehicleTypes
PATCH /vehicle-types/:id   authenticateToken + requireRole("super_admin") → updateVehicleType
Register in app.ts under /api/vehicle-types.
Step 2 -- Update vehicle endpoints to include vehicle type
In vehicleController.ts, update listVehicles and searchVehicles to JOIN vehicle_types and return vehicleTypeId and vehicleTypeName for each vehicle. Trip Admins need this during trip creation to know the type of the selected vehicle.
Also update createVehicle -- the request body should now accept vehicleTypeId (required, UUID, must exist in vehicle_types). Store it on the vehicle row.
Update the PATCH /vehicles/:id endpoint (updateVehicle) to also accept vehicleTypeId as an optional updatable field.
Step 3 -- Update trip creation fee logic
In artifacts/api-server/src/controllers/tripController.ts, find createTrip. Replace the current fee logic entirely:
Remove:

The state loading_rate/unloading_rate lookup (these columns no longer exist)
The fees.loadingFee and fees.unloadingFee from the request body
The fees.stakeholders[] array from the request body (stakeholder fees are now fully server-side from the pricing chart)

Add:

Look up the vehicle's vehicle_type_id from the vehicles table using vehicleId
If the vehicle has no vehicle_type_id, return 422 "Vehicle has no type assigned. Please contact your administrator."
Fetch the vehicle type's loading_fee and unloading_fee
Fetch the active pricing chart. If none exists, return 422 "No active pricing chart. Please contact your Super Admin."
Fetch all stakeholder rates for this vehicle type from pricing_chart_stakeholder_rates where vehicle_type_id = vehicleType.id and pricing_chart_id = activeChart.id
For each stakeholder rate where amount > 0, allocate that fee
For stakeholder rates where amount = 0, skip entirely (no fee row, no wallet credit)

Fee allocation (same tables as before):

Loading fee → trip_fees row with recipient_type='state', recipient_id=loadingStateId, fee_type='loading', amount=vehicleType.loadingFee
Unloading fee → trip_fees row with recipient_type='state', recipient_id=unloadingStateId, fee_type='unloading', amount=vehicleType.unloadingFee
Each non-zero stakeholder → trip_fees row with recipient_type='stakeholder', recipient_id=stakeholderId, fee_type='stakeholder_fee', amount=rate.amount
Wallet credits and ledger entries for each fee row as before

Add vehicleTypeId and vehicleTypeName to the trip creation response.
