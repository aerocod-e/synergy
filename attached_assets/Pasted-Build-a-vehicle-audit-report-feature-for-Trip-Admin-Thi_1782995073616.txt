Build a vehicle audit report feature for Trip Admin. This is the first of three planned audit types, vehicle, driver, and Trip Admin, all sharing the same underlying pattern, so build the shared pieces with reuse in mind.
Step 1, backend, new audit endpoint.
Create a new endpoint GET /api/audit/vehicles in a new controller auditController.ts. Trip Admin only. Accepts query params, vehicleId optional, if omitted return combined data for every vehicle owned by the calling Trip Admin, dateFrom optional, dateTo optional, status optional, matching trip status values.
For each vehicle in scope, return, vehicle id, registration number, vehicle type name, date registered, a trip list, each trip with trip code, date, route as loading state name and unloading state name, status, driver name, total fees generated on that trip meaning loading fee plus unloading fee plus every stakeholder fee combined, and per vehicle summary numbers, total trips, completed count, cancelled count, in transit count, created count, total revenue generated across the filtered set, cancellation breakdown as direct cancellation count versus went through approval count.
Scope every query to created_by = req.user.userId so a Trip Admin only ever sees their own vehicles.
Register the route in a new routes/audit.ts file, authenticateToken plus requireRole("trip_admin").
Step 2, frontend, entity picker.
On (tripadmin)/vehicles.tsx, add a button labeled Generate Audit above the vehicle list, right side, same row as any existing header content. Tapping it opens a small modal with two choices, All Vehicles, or Select a Vehicle which shows a searchable list of the Trip Admin's own vehicles to pick one. Either choice navigates to a new shared audit report screen, passing either no vehicleId, meaning combined, or a specific vehicleId.
Step 3, frontend, shared audit report screen.
Create artifacts/mobile/app/(tripadmin)/audit-report.tsx. Register as a hidden screen, href: null, in (tripadmin)/_layout.tsx, and add audit-report to HIDDEN_ROUTES in PillTabBar.tsx.
The screen reads vehicleId from route params, if present shows a single vehicle report, if absent shows the combined report.
Layout, top section, entity name if single vehicle mode, or All Vehicles heading if combined, date range filter with presets, Last 7 days, Last 30 days, This month, Last month, Custom range with from and to date pickers, status filter as a row of filter pills, matching the visual style already used elsewhere in the app for status pills.
Below the filters, summary numbers block, styled as cards consistent with existing card design, total trips, completed, cancelled, in transit, created, total revenue formatted in Naira, cancellation breakdown.
Below that, the detailed trip table. In single vehicle mode this is a flat list of that vehicle's trips. In combined mode, group by vehicle, each vehicle gets its own header row showing registration number and its own mini summary line, trip count, completion percentage, revenue, followed by that vehicle's trips, then the next vehicle's group begins.
Two buttons at the bottom, Export PDF and Export Excel.
Step 4, frontend, PDF export.
Install expo-print and expo-sharing if not already present. Build an HTML string representing the same content shown on screen, clean formatted header, summary block, then the grouped or flat table. Use Print.printToFileAsync to generate the PDF, then Sharing.shareAsync to hand it to the native share sheet.
Step 5, frontend, Excel export.
Install xlsx if not already present. Build a workbook in memory matching the same data, one sheet per vehicle in combined mode, or one sheet in single vehicle mode, with a summary row block at the top of each sheet followed by the trip rows. Write the file to a temporary location using expo-file-system, then hand it to the same native share sheet via expo-sharing.
Step 6, TypeScript check, both packages.
pnpm --filter @workspace/api-server exec tsc --noEmit
pnpm --filter @workspace/mobile exec tsc --noEmit
Both must return zero errors.
