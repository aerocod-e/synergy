Add license expiry tracking and full update history to drivers, and block new trip creation for drivers with an expired license. Follow all steps in order.
Database
Add license_expiry_date to drivers, a date column, nullable for now to avoid breaking existing rows, but required going forward on all new registrations.
Create a new table driver_license_history:
sqlCREATE TABLE IF NOT EXISTS driver_license_history (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  driver_id UUID NOT NULL REFERENCES drivers(id),
  old_license_number VARCHAR(100),
  new_license_number VARCHAR(100) NOT NULL,
  old_expiry_date DATE,
  new_expiry_date DATE NOT NULL,
  changed_by UUID REFERENCES users(id),
  changed_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW()
);
Backend
Update createDriver to require licenseExpiryDate in the request body going forward, validate it is a valid date.
Add a new endpoint, PATCH /api/drivers/:id/license, trip admin only, must be created_by. Accepts licenseNumber and licenseExpiryDate, both required together. Before updating the driver row, insert a row into driver_license_history capturing the driver's current license_number and license_expiry_date as the old values, and the newly submitted values as the new ones, along with changed_by set to the calling trip admin. Then update the driver's license_number and license_expiry_date to the new values.

Add GET /api/drivers/:id/license-history, trip admin only, must be created_by, returns all driver_license_history rows for that driver ordered by changed_at descending.

This check only applies at the moment of trip creation, existing trips already in progress are never affected.
