Backend Tests
Test 1 -- Trip codes backfilled correctly:

Query the database. Confirm every trip has a non-null, unique trip_code in the format SYN-YYYY-NNNNNN.
Test 2 -- New trip creation generates a trip code:

Login as test.lagos.tripadmin@synergy.com, create a new trip. Confirm the response includes a properly formatted tripCode.
Test 3 -- Public search works with no auth:

Without any auth token, call GET /api/lookup/trips/search?q=SYN-2026 (or a real trip code prefix). Expected: 200 with matching results, no 401/403.
Test 4 -- Search by driver name:

Call the same endpoint with a known driver's name as q. Expected: matching trip(s) returned.
Test 5 -- Search by vehicle number:

Call with a known vehicle registration number as q. Expected: matching trip(s) returned.
Test 6 -- Payment status structure present:

Confirm each result in the response includes a paymentStatus object with loading, unloading, and a stakeholders array, each with a status of paid or pending.
Test 7 -- Old vehicle lookup endpoint still works:

Call GET /api/lookup/vehicle/:vehicleNumber with a known vehicle number. Confirm it still returns 200 with the same response shape as before -- unaffected by this feature.
Test 8 -- Rate limiting still applies:

Confirm the new search endpoint is using the same publicLookupLimiter as the existing public endpoint.
