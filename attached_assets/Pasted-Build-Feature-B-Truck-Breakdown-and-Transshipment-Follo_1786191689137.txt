Build Feature B, Truck Breakdown and Transshipment. Follow all steps in order.

Backend

Add two new values to the shared trip status source of truth, breakdown and transshipment_in_transit, in constants/tripStatus.ts. Add both to TRIP_STATUSES and TRIP_STATUS.

Add a new table, trip_transshipment_history, columns: id UUID primary key, trip_id UUID REFERENCES trips(id), old_vehicle_id UUID REFERENCES vehicles(id) nullable, new_vehicle_id UUID REFERENCES vehicles(id) nullable, old_driver_id UUID REFERENCES drivers(id) nullable, new_driver_id UUID REFERENCES drivers(id) nullable, changed_by UUID REFERENCES users(id), changed_at TIMESTAMPTZ NOT NULL DEFAULT NOW(). Both old and new columns are nullable since a single swap event may change only the vehicle, only the driver, or both.

In tripController.ts, add two new functions.

markTripBreakdown, accepts a trip id, guarded authenticateToken, requireRole("trip_admin"). Row-locks the trip with SELECT FOR UPDATE, verifies created_by matches the caller, verifies current status is created or in_transit, sets status to breakdown, inserts a trip_events row with event_type breakdown_marked. Return the updated trip.

markTransshipment, accepts a trip id, and in the body newVehicleId optional, newDriverId optional, at least one of the two is required, reject with a clear message if both are missing. Row-locks the trip, verifies created_by matches the caller, verifies current status is breakdown, verifies any provided newVehicleId belongs to this trip admin and is not currently on another active trip, verifies any provided newDriverId belongs to this trip admin and has a valid, non-expired license. Inside a transaction, insert one row into trip_transshipment_history capturing the trip's current vehicle_id and driver_id as old values and whichever new ids were provided as new values, only overwriting the field on the trips row that was actually provided, leaving the other one unchanged if it was not part of this swap. Set trips.status to transshipment_in_transit. Insert a trip_events row with event_type transshipment. Do not touch trip_fees, wallet_ledger, or wallets in any way, the trip's originally recorded fees must remain byte for byte unchanged regardless of this update. Return the updated trip.

Register both under existing trip routes: PATCH /trips/:id/breakdown and PATCH /trips/:id/transshipment, same guard pattern already used for start and complete.

Add getTripTransshipmentHistory, accepts a trip id, guarded authenticateToken, requireRole("trip_admin", "state_admin", "super_admin"), scoped so a trip_admin can only fetch history for a trip they created, returns every row for that trip ordered changed_at ascending, with vehicle registration numbers and driver names resolved rather than raw ids, following the exact resolved-name pattern already used in getDriverLicenseHistory.

Update getTripById to also return this trip's transshipment history array whenever it is non-empty, and to include whichever vehicle and driver are currently assigned, which will already reflect the most recent swap since those columns were updated directly on the trip.

Update every place trip status is currently branched on across the backend that would need to correctly handle these two new values without breaking, specifically the active-trip checks in vehicleController.ts, driverController.ts, and userController.ts, since a trip in breakdown or transshipment_in_transit is still an active trip and must still block deleting or editing its vehicle or driver. Confirm this explicitly by tracing the shared constant rather than assuming.
